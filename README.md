## 🧩 Problem-Solving Approach

For every problem, I try to follow this process:

``text
1. Understand the problem
        ↓
2. Identify the pattern
        ↓
3. Think of a brute-force solution
        ↓
4. Analyze Time & Space Complexity
        ↓
5. Optimize the solution
        ↓
6. Write the Java code
        ↓
7. Test with different cases
        ↓
8. Write notes and learn from mistakes
```

---

## 📝 How I Document Problems

For important problems, I try to maintain notes containing:

* Problem statement
* Approach
* Key observation
* Algorithm
* Java solution
* Time complexity
* Space complexity
* Edge cases
* Mistakes / lessons learned

Example:

``text
Problem: Two Sum

Pattern:
HashMap

Approach:
Store previously seen numbers and check whether
the required complement already exists.

Time Complexity:
O(n)

Space Complexity:
O(n)
```

```
## 💡 Lessons I'm Learning

DSA is not about memorizing hundreds of solutions.

It is about learning to recognize:

text
Problem
   ↓
Pattern
   ↓
Approach
   ↓
Data Structure
   ↓
Algorithm
   ↓
Optimization
```

Every wrong solution is also part of the journey.

---

## 📌 My Rules

* Understand the problem before coding.
* Don't immediately look at the solution.
* Try brute force first.
* Always analyze complexity.
* Learn patterns instead of memorizing code.
* Revise previously solved problems.
* Keep improving old solutions.
* Be consistent.
